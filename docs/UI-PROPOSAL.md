# 界面改版方案（第三轮）

> 写于 2026-11-26。前面几轮都在调颜色、圆角、车模大小，但反馈是「怎么调都不好看」——
> 这说明问题不在细节，在**结构**。这份文档先说诊断，再给三个方案，最后给推荐方案的具体规格。

## 一、诊断：现在的问题

把 3.1～3.2 的首页截图拆开看，一屏里有 **6 个独立的玻璃块**：

```
[ 车模卡 ]
[ 控制卡：4 个圆钮 × 2 行 + 更多 ]
[ 电量 ] [ 温度 ]        ← 两个小卡
[ 车门 车窗 胎压 行程 ]   ← 一个状态卡
[ 位置缩略图 ]
[ Tab Bar ]
```

每一块都带同样的圆角、同样的玻璃、同样的描边、同样大小的留白 —— 结果是：

1. **没有主次**。视线在 6 个同权重的块之间跳，找不到「先看哪儿」。
2. **呼吸被切碎**。块与块之间的 14pt 空隙重复五次，页面成了「一堆盒子」，而不是「一页」。
3. **数字散落**。60%、252km、23°C 分散在三块里，每个都不够大，谁也不是主角。
4. **嵌套**。控制条外面还套一层卡片，按钮本身又是圆形——两层框套一层框。
5. **车模没有归属**。即使做了展台，它仍然是一块「插在页面里的图」，因为上下左右都是同质卡片。

结论：**不是配色不对，是「块太多、层级太平」**。

## 二、参考过的开源项目

Gitee 的搜索是前端渲染的、开放接口不对外，匿名搜「零跑」拿不到结果；实际能读到的同类项目都在 GitHub，
一共五个，界面思路各不相同：

| 项目 | 形态 | UI 上值得抄的 | 不值得抄的 |
| --- | --- | --- | --- |
| [leapmotor-mate-cn](https://github.com/pipipiper/leapmotor-mate-cn) | Web 仪表盘 | 数据密度高、每张卡只说一件事；记录页的日历+时间线 | 桌面端布局，手机上一屏塞不下 |
| [LeapMore](https://github.com/MiRaToo/LeapMore) | Web（PWA） | 3D 首页 + 时间线记录；顶部一个大数字 | 功能入口太多，首页像个菜单 |
| [**leapauto**](https://github.com/stephenwang1011/leapauto) | Android Compose | **单张 hero 占上半屏**、中性配色、状态胶囊极小、控制一行四个 | 车机主题花样多，手机端用不上 |
| [C11Partner](https://github.com/Mariobolo/C11Partner) | 车机桌面 | 开关平铺、状态栏常驻 | 车机横屏，比例完全不同 |
| [ha-leapmotor-cn](https://github.com/MiRaToo/ha-leapmotor-cn) | HA 卡片 | 权限门控、失败可见 | 卡片是给仪表盘拼的，不是 App |

三个手机/网页端的共同点，也是我们现在缺的：

- **一屏只有一个主角**（车，或者续航），其余都是配角。
- **卡片数量少**：leapauto 首页只有 hero + 两组行，没有 6 个并列块。
- **数字只放一个地方**，而且很大。
- **颜色只表达状态**，界面本身是灰的。

## 三、三个方案

### 方案 A：一屏一主角（推荐）

```
┌──────────────────────────────┐
│  昵称 · 更新时间        ⚙️  📍 │   ← 无卡片，直接压在 hero 上
│                              │
│          [ 3D 车 ]            │   ← hero 占 44% 屏高，无边框
│                              │
│   已锁车 · 哨兵关 · 4 门已关     │   ← 一枚小胶囊
│                              │
│  512   km          60%  23°C  │   ← 唯一的「大字」是续航
├──────────────────────────────┤
│  ⬤    ⬤    ⬤    ⬤           │   ← 控制卡（一块，无内嵌卡片）
│ 上锁  空调  尾门  更多          │
├──────────────────────────────┤
│  车门 4/4 关 · 车窗 已关        │   ← 状态卡（一块，行式）
│  胎压 正常 · 行程 今日 52km     │
└──────────────────────────────┘
```

- **块数：6 → 3**（hero + 控制 + 状态），位置缩略图并进状态卡的一行。
- **唯一主数字：续航**（36pt），电量/温度是 17pt 的配角。
- 控制条不再包一层玻璃，直接坐在 hero 下沿（或独立一块但去掉内嵌圆底）。
- 优点：层级清楚、呼吸够、和官方 App 的观感最接近。代价：要重排首页骨架，改动最大。

### 方案 B：数据优先

hero 缩到 28%，四宫格（续航/电量/温度/胎压）占主位，控制条横滑。

- 优点：天天看数的人最顺手；缺点：车成了缩略图，失去了「看一眼车」的情绪价值。

### 方案 C：官方 App 复刻

完全照零跑 App：顶部车图卡（渐变遮罩 + 车名 + 续航）→ 横滑快捷控制 → 状态卡列表。

- 优点：最稳、零学习成本；缺点：没有识别度，且官方 App 的卡片流在 iPhone 上偏松。

## 四、推荐：方案 A 的具体规格

| 项 | 规格 |
| --- | --- |
| 页面留白 | 左右 20（现在是 16），块间距 16 |
| hero | 高 = 屏高 × 0.44，**无卡片无描边**，底图直接是页面渐变，车压在渐变上 |
| hero 上的信息 | 左上：昵称 + 更新时间（13pt）；右上：设置/位置（圆形玻璃小钮 34pt） |
| 状态胶囊 | 高 24、字号 11、半透明底，最多 3 枚 |
| 主数字 | 续航 36pt semibold rounded；单位 13pt；下面一行 11pt「CLTC · 满电 610」 |
| 次数字 | 电量 / 车内温度 17pt，放在主数字右侧，用一条 1pt 竖线隔开 |
| 控制卡 | 一块玻璃，4 个圆钮 46pt，下面 11pt 标签；「更多」放下方居中胶囊 |
| 状态卡 | 行式，每行：图标 20 + 标题 14 + 值 14（右对齐），行间 1pt 分隔；最多 4 行 |
| 圆角 | 卡片 24、控制卡 24、胶囊 12 |
| 颜色 | 中性底 + 绿（能量）+ 红（异常），沿用 3.1 的令牌 |
| Tab | 4 项不变，选中用墨色，不用彩色 |

**为什么这样就不「块」了**：hero 没有边框、直接长在页面上；下面只有两块玻璃；
所有块共用同一套 16pt 节奏；一屏最多三块，眼睛有落点。

## 五、实施批次

1. **第一批（骨架）**：hero 去掉卡片与描边、并入昵称/续航/状态胶囊；页面留白 16→20；
   块数减到 3。验收点：截图里只剩 3 块。
2. **第二批（控制）**：控制条去掉内嵌圆底、按钮 46pt、标签 11pt；「更多」改居中胶囊。
3. **第三批（状态）**：状态卡改行式，把位置缩略图并成一行；胎压/门窗用红点表异常。

每批都是独立可回滚的提交，随时可以停在某一批。

## 六、需要你定的事

1. 选 A / B / C（我建议 A）。
2. hero 要不要保留「昵称 + 更新时间」在左上？还是像官方 App 那样放到导航栏？
3. 主数字用**续航**还是**电量百分比**？（我建议续航，因为百分比在车机上更常见，但续航更「车」）
